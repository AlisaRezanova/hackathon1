# Exit Intelligence — задание хакатона

## Проблема и пользователь
HR-менеджер/HR-директор вручную читает и анализирует exit-интервью. Аналитика делается "на
глаз", поэтому системные проблемы (процессы, микроклимат, зарплаты) всплывают с опозданием
на 2–3 месяца — компания реагирует, когда уже поздно.

## Ценностное предложение
AI проводит exit-интервью сам (чат с уточняющими вопросами), превращает его в
структурированный "паспорт проблемы", а из всех интервью — в кластеризованный дашборд
топ-причин ухода по компании с разбором до конкретных цитат.

## Основной сценарий демо (≤90 сек)
1. `/interviews`: открываем чат-интервью. Бот задаёт 3 базовых вопроса по очереди (отдел,
   должность, "опишите своими словами главную проблему"), затем сам, без фиксированного
   сценария, задаёт 2–3 уточняющих вопроса по LLM, углубляя причину.
2. По завершении чат сразу показывает "паспорт проблемы": `primary_category`, `risk_zone`,
   кластеризованные `categories` (категория → подтип → цитата), `best_practices`,
   ≥3 `improvement_suggestions`, график `sentiment_arc`. Видно, кто это построил — `llm`
   или резервная эвристика.
3. `/analytics`: дашборд по всем интервью (12 seed + только что пройденное) — % по
   категориям ("48% — проблемы с руководством, 32% — карьерный рост"), risk по отделам.
   Клик по категории → drill-down: AI-саммари по кластеру, подтипы, типичные сценарии,
   цитаты из реальных интервью.

## Wow-момент
Кто-то из жюри садится и проходит exit-интервью с ботом вживую: без заранее заданной
анкеты, ИИ сам докапывается до истинной причины уточняющими вопросами — а на дашборде сразу
видно, как его ответ подвинул проценты по компании.

## Что сознательно не делаем
- Анкету для рассылки действующим сотрудникам на подтверждение проблемы (Google Forms
  и т.п.) — явно вне скоупа по решению команды.
- Загрузку датасета файлом (CSV/DF) — входные данные теперь только из чата (демо-датасет
  в `seed.py`) или вставки текста как fallback.
- Человека-модератора, подтверждающего каждую новую категорию до её появления в базе —
  категории свободные (см. ниже), без ручного approval-гейта.
- Безлимitный чат: жёстко ограничиваем 3 базовых + до 3 уточняющих вопроса, чтобы демо было
  предсказуемым по времени и стоимости LLM-вызовов.
- Авторизацию, роли, историю изменений, Telegram-бота, дообучение моделей.

## Контракт между фичами (`backend/app/models.py`, заморожено)
- `Department` — отдел (5 демо-отделов).
- `ExitInterview` — транскрипт: alias, позиция, отдел, дата, текст, `source`
  (`seed`/`chat`).
- `ExitAnalysis` (1:1 к интервью) — "паспорт проблемы": `primary_category` (топ-1 причина,
  свободная строка — набор причин не фиксирован, новые появляются сами), `risk_zone`,
  `categories[]` (`{category, subtype, quote}` — нормализация + кластеризация для
  дашборда), `best_practices[]`, `improvement_suggestions[]`, `sentiment_arc[]`,
  `generated_by` (`llm`/`heuristic`).
`scripts/seed.py` заливает 12 готовых транскриптов с готовым `ExitAnalysis` (уже
кластеризованных) — `analytics` не ждёт живого чат-пайплайна `interviews`.

## Задача Кости — основной сценарий + интеграция (`features/interviews`)
1. Чат-эндпоинт (например `POST /api/interviews/chat`) — по накопленной истории
   вопрос-ответ отдаёт следующий вопрос: первые 3 вопроса фиксированы (без LLM, для
   надёжности), дальше — уточняющие через OpenRouter, максимум 3; при пустом ключе/сбое —
   заранее заданные резервные уточняющие вопросы.
2. `POST /api/interviews/analyze` — собранный транскрипт → `ExitAnalysis`
   (`primary_category`, `categories`, `risk_zone` и т.д.) через LLM с heuristic-fallback
   (обязателен по правилам репо); сохраняет `ExitInterview(source="chat")`.
3. `GET /api/interviews` — список интервью (seed + пройденные вживую) для истории/пресетов.
4. `frontend/src/features/interviews`: чат-виджет (вопрос → ответ → следующий вопрос) +
   карточка итогового паспорта; альтернативная кнопка "вставить готовый транскрипт" как
   быстрый fallback-путь для демо.
5. Финальная интеграция: `make check`, оба маршрута из Sidebar, общий commit. Не трогает
   `features/analytics/*`.

## Задача Алисы — аналитика по компании (`features/analytics`)
1. `GET /api/analytics/summary` — % по `primary_category`/`categories` среди всех
   `ExitAnalysis`, разбивка `risk_zone` по отделам.
2. `GET /api/analytics/categories/{category}` — drill-down: подтипы, count, цитаты,
   короткое AI-саммари кластера (можно эвристически из `categories`/`improvement_suggestions`,
   без обязательного живого LLM-вызова).
3. `frontend/src/features/analytics`: StatCard'ы по % причин, таблица risk по отделам,
   список категорий с переходом в drill-down (подтипы + цитаты + саммари).
4. Читает только `ExitInterview`/`ExitAnalysis` из seed-данных (+ то, что уже насчитал
   Костя в базе) — не дёргает `/api/interviews/chat`. Не трогает `features/interviews/*`.

## Каталоги/файлы
- Костя: `backend/app/features/interviews/**`, `frontend/src/features/interviews/**`.
- Алиса: `backend/app/features/analytics/**`, `frontend/src/features/analytics/**`.
- Общее, не трогать: `models.py`, `seed.py`, `main.py`, `router.tsx`, `config.py`,
  `docker-compose.yaml`, `Makefile`.

## Критерии готовности задачи
- Костя: чат от 3 базовых до уточняющих вопросов доходит до паспорта проблемы на
  `/interviews`, видно `llm`/`heuristic`; `make check` зелёный.
- Алиса: `/analytics` показывает % по категориям, risk по отделам и drill-down с цитатами
  по всем seed-интервью без ошибок; `make check` зелёный.

## Порядок интеграции
1. Каждый работает в своей паре папок через `make dev` локально — первая рабочая версия
   ожидается ~через 35 минут.
2. За 15–20 минут до конца — Костя сводит: оба маршрута открываются из Sidebar, `make
   check` зелёный, финальный commit (без слияния чужой ветки без договорённости).

## Общий критерий готовности продукта
`make dev` поднимает всё с одного захода; чат-интервью на `/interviews` доходит до паспорта
проблемы, `/analytics` показывает реальные (не ping) агрегаты с drill-down; ни одной
сломанной видимой кнопки; демо проходит офлайн на heuristic fallback, с сетью — с реальным
LLM-вызовом.

## План презентации
1. Визитка: команда + кейс "Exit Intelligence".
2. Инструменты ИИ: LLM (OpenRouter, open-source модель) ведёт адаптивное интервью и строит
   паспорт проблемы + кластеризацию причин; heuristic-fallback как подстраховка.
3. Логика: чат-интервью → LLM/эвристика → паспорт → нормализация/кластеризация → дашборд.
4. Демо: сценарий выше (interviews → analytics), при возможности — живое интервью с жюри.
5. Эффект: HR видит системные причины ухода сразу, а не через 2–3 месяца, вплоть до
   конкретных цитат сотрудников.
6. Сложности: задание ограничивает выбор LLM open-source моделями — закрыли через
   OpenRouter с graceful fallback на эвристику.
