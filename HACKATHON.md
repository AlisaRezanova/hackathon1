# Exit Intelligence — задание хакатона

## Проблема и пользователь
HR-менеджер/HR-директор вручную читает и анализирует exit-интервью (текстовые
транскрипты бесед с увольняющимися). Аналитика делается "на глаз", поэтому системные
проблемы (процессы, микроклимат, зарплаты) всплывают с опозданием на 2–3 месяца — компания
реагирует, когда уже поздно.

## Ценностное предложение
За секунды превращаем сырой транскрипт exit-интервью в структурированный "паспорт
проблемы", а из нескольких интервью — в дашборд с топ-причинами ухода по всей компании.

## Основной сценарий демо (≤90 сек)
1. `/interviews`: выбираем один из готовых демо-транскриптов (или вставляем свой текст) →
   жмём "Проанализировать".
2. За секунды видим "паспорт проблемы": `exit_reason`, `pain_points` с частотой упоминаний,
   `best_practices` с цитатами, `risk_zone`, ≥3 `improvement_suggestions` и мини-график
   тональности разговора (`sentiment_arc`).
3. `/analytics`: дашборд по всем 12 seed-интервью — % топ-причин ухода, risk по отделам,
   самые частые проблемы компании, сгенерированные рекомендации для топ-менеджмента.

## Wow-момент
На сцене разбираем текст, которого не было в демо-датасете (можно взять кейс от жюри) —
LLM (OpenRouter) за секунды строит полный паспорт проблемы с графиком тональности по ходу
диалога, и сразу видно, как он меняет проценты на общем дашборде.

## Что сознательно не делаем
- Живое адаптивное интервью с уточняющими вопросами в реальном времени — задание даёт уже
  готовые транскрипты, это не входит в скоуп.
- Загрузку .docx/.pdf — только вставка текста / выбор пресета (можно расширить до .txt).
- Авторизацию, роли, историю изменений, Telegram-бота.
- Дообучение моделей — только промпт-инжиниринг.

## Контракт между фичами (`backend/app/models.py`, заморожено)
- `Department` — отдел (5 демо-отделов).
- `ExitInterview` — сырой анонимизированный транскрипт: alias, позиция, отдел, дата, текст.
- `ExitAnalysis` (1:1 к интервью) — "паспорт проблемы": `exit_reason`, `risk_zone`,
  `pain_points[]`, `best_practices[]`, `improvement_suggestions[]`, `sentiment_arc[]`,
  `generated_by` (`llm` | `heuristic`).
`scripts/seed.py` заливает 12 готовых транскриптов + для каждого готовый `ExitAnalysis` —
`analytics` не ждёт живого пайплайна `interviews`, обе фичи читают только demo-данные.

## Задача Кости — основной сценарий + интеграция (`features/interviews`)
1. `POST /api/interviews/analyze` — текст транскрипта → `ExitAnalysis`: вызов LLM через
   OpenRouter (`OPENROUTER_API_KEY`/`OPENROUTER_MODEL` в `.env`, модель — open-source,
   деньги в `.env` не коммитить); при пустом ключе или сбое запроса — эвристический
   fallback по ключевым словам/маркерам эмоций (обязателен по правилам репо).
2. `GET /api/interviews` — список seed-транскриптов для пресетов в UI.
3. `frontend/src/features/interviews`: выбор пресета / textarea, кнопка анализа, карточка
   паспорта (reason/risk бейджи, pain points, цитаты, список рекомендаций, sentiment-график
   — можно простым SVG/полоской). Явно показывать `generated_by` (LLM или fallback).
4. Финальная интеграция перед демо: прогнать `make check`, проверить оба маршрута из
   Sidebar, сделать общий commit.
5. Не трогает `features/analytics/*`.

## Задача Алисы — аналитика по компании (`features/analytics`)
1. `GET /api/analytics/summary` — % по `exit_reason` среди всех `ExitAnalysis`, разбивка
   `risk_zone` по отделам, топ повторяющихся `pain_points` по всей базе.
2. Company summary: 3–5 рекомендаций топ-менеджменту — агрегируются эвристически из
   `improvement_suggestions` всех интервью (без повторного вызова LLM).
3. `frontend/src/features/analytics`: StatCard'ы по % причин, таблица/бейджи риска по
   отделам, список топ pain points, карточка с рекомендациями.
4. Читает только `ExitInterview`/`ExitAnalysis` из seed-данных, не дёргает
   `/api/interviews/analyze`.
5. Не трогает `features/interviews/*`.

## Каталоги/файлы
- Костя: `backend/app/features/interviews/**`, `frontend/src/features/interviews/**`.
- Алиса: `backend/app/features/analytics/**`, `frontend/src/features/analytics/**`.
- Общее, не трогать: `models.py`, `seed.py`, `main.py`, `router.tsx`, `config.py`,
  `docker-compose.yaml`, `Makefile`.

## Критерии готовности задачи
- Костя: пресет-транскрипт на `/interviews` даёт полный паспорт (все поля + sentiment),
  видно `llm`/`heuristic`; `make check` зелёный.
- Алиса: `/analytics` показывает % причин, risk по отделам и топ pain points по 12
  seed-интервью без ошибок; `make check` зелёный.

## Порядок интеграции
1. Каждый работает в своей паре папок через `make dev` локально — первая рабочая версия
   ожидается ~через 35 минут.
2. За 15–20 минут до конца — Костя сводит: оба маршрута открываются из Sidebar, `make
   check` зелёный, финальный commit (без слияния чужой ветки без договорённости).

## Общий критерий готовности продукта
`make dev` поднимает всё с одного захода; `/interviews` и `/analytics` показывают реальные
(не ping) данные; ни одной сломанной видимой кнопки; демо проходит за ≤90 сек офлайн
(heuristic fallback), с сетью — с реальным LLM-вызовом.

## План презентации
1. Визитка: команда + кейс "Exit Intelligence".
2. Инструменты ИИ: LLM (OpenRouter, open-source модель) парсит транскрипт в паспорт
   проблемы; heuristic-fallback как демонстрационная подстраховка.
3. Логика: транскрипт → LLM/эвристика → паспорт → агрегация → дашборд компании.
4. Демо: сценарий выше (interviews → analytics).
5. Эффект: HR видит системные причины ухода сразу, а не через 2–3 месяца; готовые гипотезы
   по топ-1 проблеме.
6. Сложности: задание ограничивает выбор LLM open-source моделями — закрыли через
   OpenRouter с graceful fallback на эвристику.
