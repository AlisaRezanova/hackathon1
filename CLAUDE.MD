# Hackathon mode

Это репозиторий прототипа для двухчасового хакатона.

## Приоритеты

1. Понятная ценность для конкретного пользователя.
2. Полностью работающий демонстрационный сценарий.
3. Визуальная убедительность и хорошие демоданные.
4. Надежность запуска.
5. Только затем — техническая чистота.

## Правила реализации

- Перед работой прочитай `HACKATHON.md`.
- Реализуй только задачу и файлы, назначенные текущему участнику; делить работу — по фичам, а не по слоям frontend/backend.
- Не изменяй файлы другого участника без явной договоренности.
- Не редактируй `HACKATHON.md` после начала параллельной работы.
- Самостоятельно принимай некритичные решения по UI/UX и реализации.
- Задавай вопрос только тогда, когда ответ существенно меняет продукт.
- Backend, PostgreSQL и Docker/Docker Compose — часть согласованного стека; frontend на моковых данных/localStorage используй только как временный fallback, если backend в моменте недоступен.
- Не добавляй авторизацию, лишние сервисы, БД или инфраструктуру сверх согласованного стека (backend + PostgreSQL + Docker Compose), если без них можно показать пользовательскую ценность.
- Не делай больших рефакторингов и не меняй стек во время хакатона.
- Не запускай subagents и другие параллельные AI-процессы.
- Все видимые кнопки должны работать либо быть удалены.
- Для внешних AI/API-функций делай демонстрационный fallback.
- Не используй настоящие персональные данные.

## Завершение задачи

- Пройди назначенный пользовательский сценарий.
- Запусти lint и build.
- Проверь интерфейс в браузере.
- Сообщи измененные файлы, результат проверок и известные ограничения.
- Сделай небольшой осмысленный commit, но не сливай чужую ветку самостоятельно.
